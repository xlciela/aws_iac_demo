# VPC Peering 管理控制台操作指南

## 步骤1: 创建两个VPC

### 1.1 创建VPC A
1. 登录AWS管理控制台
2. 导航到 **VPC** 服务
3. 点击 **创建VPC**
4. 配置VPC A:
   - **名称标签**: VPC-A
   - **IPv4 CIDR块**: `10.0.0.0/16`
   - **IPv6 CIDR块**: 无IPv6 CIDR块
   - **租户**: 默认
5. 点击 **创建VPC**

### 1.2 创建VPC B
重复上述步骤，配置VPC B:
- **名称标签**: VPC-B
- **IPv4 CIDR块**: `10.1.0.0/16`

## 步骤2: 为每个VPC创建子网

### 2.1 VPC A 子网
1. 在VPC控制台，点击 **子网**
2. 点击 **创建子网**
3. 创建公有子网:
   - **VPC ID**: 选择VPC-A
   - **子网名称**: VPC-A-Public-Subnet
   - **可用区**: ap-northeast-1a
   - **IPv4 CIDR块**: `10.0.1.0/24`
4. 创建私有子网:
   - **子网名称**: VPC-A-Private-Subnet
   - **可用区**: ap-northeast-1a
   - **IPv4 CIDR块**: `10.0.2.0/24`

### 2.2 VPC B 子网
重复上述步骤为VPC B创建子网:
- 公有子网: `10.1.1.0/24`
- 私有子网: `10.1.2.0/24`

## 步骤3: 创建VPC Peering连接

### 3.1 发起Peering请求
1. 在VPC控制台，点击 **对等连接**
2. 点击 **创建对等连接**
3. 配置Peering连接:
   - **对等连接名称标签**: VPC-A-to-VPC-B-Peering
   - **VPC (请求方)**: 选择VPC-A
   - **账户**: 我的账户
   - **区域**: 此区域 (ap-northeast-1)
   - **VPC (接受方)**: 选择VPC-B
4. 点击 **创建对等连接**

### 3.2 接受Peering请求
1. 创建后，状态显示为 **待接受**
2. 选择刚创建的Peering连接
3. 点击 **操作** → **接受请求**
4. 确认接受请求
5. 状态变为 **活跃**

## 步骤4: 配置路由表

### 4.1 创建VPC A的路由表
1. 点击 **路由表**
2. 点击 **创建路由表**
3. 配置:
   - **名称**: VPC-A-RouteTable
   - **VPC**: 选择VPC-A
4. 点击 **创建路由表**

### 4.2 添加VPC A到VPC B的路由
1. 选择VPC-A-RouteTable
2. 点击 **路由** 标签页
3. 点击 **编辑路由**
4. 点击 **添加路由**
5. 配置路由:
   - **目标**: `10.1.0.0/16`
   - **目标**: 选择Peering连接 (VPC-A-to-VPC-B-Peering)
6. 点击 **保存更改**

### 4.3 关联VPC A的子网
1. 在VPC-A-RouteTable页面，点击 **子网关联** 标签页
2. 点击 **编辑子网关联**
3. 选择VPC A的两个子网
4. 点击 **保存关联**

### 4.4 配置VPC B的路由表
重复4.1-4.3步骤为VPC B配置:
- 路由表名称: VPC-B-RouteTable
- 添加路由目标: `10.0.0.0/16` → Peering连接
- 关联VPC B的子网

## 步骤5: 配置安全组

### 5.1 创建VPC A安全组
1. 点击 **安全组**
2. 点击 **创建安全组**
3. 配置:
   - **安全组名称**: VPC-A-SecurityGroup
   - **描述**: Allow traffic from VPC B
   - **VPC**: 选择VPC-A

### 5.2 配置VPC A安全组入站规则
1. 在 **入站规则** 标签页，点击 **编辑入站规则**
2. 添加规则:
   - **类型**: SSH, **端口**: 22, **源**: `10.1.0.0/16`
   - **类型**: 所有ICMP-IPv4, **源**: `10.1.0.0/16`
3. 点击 **保存规则**

### 5.3 配置VPC B安全组
重复5.1-5.2步骤为VPC B创建安全组:
- 安全组名称: VPC-B-SecurityGroup
- 入站规则源: `10.0.0.0/16`

## 步骤6: 创建测试EC2实例

### 6.1 创建VPC A测试实例
1. 导航到 **EC2** 服务
2. 点击 **启动实例**
3. 配置:
   - **名称**: VPC-A-Test-Instance
   - **AMI**: Amazon Linux 2
   - **实例类型**: t3.micro
   - **网络**: VPC-A
   - **子网**: VPC-A-Private-Subnet
   - **安全组**: VPC-A-SecurityGroup
4. 点击 **启动实例**

### 6.2 创建VPC B测试实例
重复6.1步骤为VPC B创建实例:
- 名称: VPC-B-Test-Instance
- 网络: VPC-B
- 子网: VPC-B-Private-Subnet
- 安全组: VPC-B-SecurityGroup

## 步骤7: 验证连接

### 7.1 检查Peering连接状态
1. 在VPC控制台，点击 **对等连接**
2. 确认状态为 **活跃**

### 7.2 检查路由表
1. 点击 **路由表**
2. 检查VPC A路由表包含到`10.1.0.0/16`的路由
3. 检查VPC B路由表包含到`10.0.0.0/16`的路由

### 7.3 获取实例私有IP
1. 在EC2控制台，点击 **实例**
2. 记录两个测试实例的私有IP地址

### 7.4 测试连接
1. 使用Session Manager连接到VPC A实例
2. 执行: `ping <VPC-B实例私有IP>`
3. 连接到VPC B实例
4. 执行: `ping <VPC-A实例私有IP>`

## 故障排除检查清单

### ✅ 检查项目:
- [ ] Peering连接状态为"活跃"
- [ ] 两个VPC的路由表都配置了对方的CIDR路由
- [ ] 安全组允许对方VPC的流量
- [ ] 实例处于运行状态
- [ ] 子网正确关联到路由表

### 常见问题:
1. **连接超时**: 检查安全组和NACL规则
2. **路由不通**: 确认路由表配置正确
3. **DNS解析问题**: 启用VPC的DNS解析和DNS主机名

## 清理资源

### 删除顺序:
1. 终止EC2实例
2. 删除VPC Peering连接
3. 删除安全组
4. 删除子网
5. 删除路由表
6. 删除VPC
