# VPC Peering 快速操作指南

## 🚀 核心操作步骤

### 1️⃣ 创建VPC Peering连接
```
VPC控制台 → 对等连接 → 创建对等连接
├── 请求方VPC: VPC-A
├── 接受方VPC: VPC-B  
└── 接受请求 → 状态变为"活跃"
```

### 2️⃣ 配置路由表（关键步骤）
```
VPC A路由表:
目标: 10.1.0.0/16 → Peering连接ID

VPC B路由表:  
目标: 10.0.0.0/16 → Peering连接ID
```

### 3️⃣ 配置安全组
```
VPC A安全组入站规则:
- SSH (22): 源 10.1.0.0/16
- ICMP: 源 10.1.0.0/16

VPC B安全组入站规则:
- SSH (22): 源 10.0.0.0/16  
- ICMP: 源 10.0.0.0/16
```

## 📋 操作检查清单

### 创建阶段:
- [ ] 两个VPC CIDR不重叠
- [ ] Peering连接状态为"活跃"
- [ ] 双向路由配置完成
- [ ] 安全组规则允许跨VPC流量

### 验证阶段:
- [ ] 实例可以ping通对方VPC的实例
- [ ] 路由表显示正确的路由条目
- [ ] 安全组规则生效

## ⚡ 快速验证命令

### 控制台检查:
1. **VPC → 对等连接**: 状态 = 活跃
2. **VPC → 路由表**: 包含对方CIDR的路由
3. **EC2 → 安全组**: 入站规则允许对方VPC

### 实例测试:
```bash
# 在VPC A实例中执行
ping <VPC-B实例私有IP>

# 在VPC B实例中执行  
ping <VPC-A实例私有IP>
```

## 🔧 常见问题解决

| 问题 | 检查项目 | 解决方案 |
|------|----------|----------|
| 无法ping通 | 安全组规则 | 添加ICMP入站规则 |
| 连接超时 | 路由表配置 | 确认双向路由存在 |
| Peering失败 | CIDR重叠 | 使用不同的CIDR块 |

## 💡 最佳实践提醒

- **网络规划**: 提前规划CIDR，避免重叠
- **最小权限**: 只开放必要的端口和协议  
- **标签管理**: 为所有资源添加清晰的标签
- **文档记录**: 记录网络拓扑和路由配置
